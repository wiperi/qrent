# QRent 房源更新内测与小 Q 助手

1. 正式首页和搜索结果在原搜索栏下收集每日更新的内测意向。QRent 后端把邮箱、语言和报名时间写进原私有 Redis 的 `qrent:rental-alerts:interest:v1`，邮箱去重。运维可在后端私有网络用 `HSCAN qrent:rental-alerts:interest:v1 0 COUNT 100` 分页读取，按返回的游标继续到 0。运营在内测开放时联系报名者，确认区域、预算和入住时间。
2. 首页和搜索页右下角打开「小 Q · AI 找房」。收起和进入完整页都保留当前标签页的对话、草稿及连接设置。访客选择 DeepSeek、Qwen 或腾讯元宝后填写对应的 Key。Qwen 使用百炼北京地域，腾讯元宝使用腾讯云 TokenHub 混元。Key 用于所选模型的请求，生命周期为当前标签页。模型接入使用开源 Vercel AI SDK。
3. 房源工具调用 QRent 原 `properties.search`，用返回的区域统计和逐套房源构造价格比较。攻略工具索引站内 10 篇经验文章和 8 篇主题手册的双语正文，按章节检索，保留来源链接、日期和适用州。
4. 先用原 GitHub CI/CD 部署报名后端，确认新接口可用，再合并前端，由原 Vercel 集成发布。验收包括真实表单写入、去重与重启读回、两种语言的租房问题、实际 API 房源统计，以及桌面和移动端的浮窗与完整对话页。
5. Domain 把邮编结尾的搜索 URL 与房源详情 URL 分开判断，原生浏览器先加载 HTML 列表，再在同一会话读取分页和已校验 ID 的详情。发布按区域独立验收，保存 403、超时与未尝试区域的原回执。按原定时入口留存采集空间检查和两类 SQLite 备份回执。

## 核验记录

- 报名后端通过 51 项原回归。隔离 Redis 测试中同一个邮箱两次提交只保留一条，Redis 正常重启后记录仍在。
- 首批两区取得 280 个 Domain 来源 ID，46 个地址经缓存校验写入或更新，88 条 MySQL 学校关联与公开 API 对齐。
- Domain 正式补采 `20261108_220906_053561` 已取得 17 区的 1,797 个来源 ID，100 条详情均匹配实际 ID。Burwood 两次超时，Haymarket 一次 403，Pyrmont、Surry Hills、Redfern 未尝试。通过验证的房源继续进入缓存发布队列。
